# Modbus Dev 用户手册

本文以 GUI 操作为主。角色、权限和寄存器区的定义见 [基本概念](modbus-basics.md)。

## 启动与公共设置

源码安装和依赖准备见 [README](../README.md)。在项目目录启动：

```sh
python -m modbus_dev ports
python -m modbus_dev gui
```

下面的 RTU 互测场景使用这些参数：

| 设置项 | 值 |
| --- | --- |
| 串口 | 各自实际连接的端口，示例 COM11/COM12 需要替换 |
| 波特率、数据格式 | 115200、8N1 |
| 站号、字节序 | 1、B1234 |
| 轮询 / 数据更新周期 | 100 ms |
| 主站周期通信预算 | 80 ms |
| RTU 从站应答写超时 | 80 ms（实际最多等待 50 ms） |
| 运行策略、时长 | 连续运行、0（手动停止） |

两端串口链路需能双向收发，同一总线只启动一个主站。先启动从站，再启动主站。
修改配置前停止会话。实际仪表或 PLC 的参数按设备说明设置。

界面按当前角色和操作启用参数，无关项隐藏或灰显，并保留原值。主站纯读取时不使用本机数据源，
后端跳过其校验和计算；从站只读时仍使用数据源。切回写入或波形生成后，相应参数重新参与校验。

## RTU 从站的数据来源

寄存器有两种更新来源：从站内部程序更新，以及主站通过 FC06/FC16 写入。
从站的“只读 / 读写”权限只控制是否接受主站写入，不限制从站内部更新。
从站内部程序可以更新输入区和保持区；外部主站只能写保持区。

本软件当前采用以下更新规则：

| 区域 | 本软件的更新方式 | 主站读取命令 |
| --- | --- | --- |
| 输入区 | 本机数据源按周期持续更新 | FC04 |
| 保持区 | 首个源值初始化一次，之后接收并保存主站写入值；只读权限下拒绝主站写入 | FC03 |

界面中的从站“数据源”用于更新输入区，并提供保持区初始值，不会持续覆盖保持区。
本软件暂未提供“本机数据源持续更新保持区”的选项，这是当前软件功能边界。

## 场景一：双方只读，读取模拟波形

用于采集程序开发、实时曲线检查和通信链路联调。从站内部生成数据，主站周期读取。
“只读”限制通信写入，不限制从站自身更新输入区。

| 设置项 | 从站电脑 | 主站电脑 |
| --- | --- | --- |
| 模式、权限 | RTU 从站、只读 | RTU 主站、只读 |
| 周期操作 | 无需设置 | FC04 · 读输入寄存器 |
| 测点 | 启用测点 1，地址 0 | 启用测点 1，地址 0 |
| 数据源 | 正弦波：中心值 10、幅值 1、频率 0.8 Hz | 灰显，不使用 |
| 写后读回 | 无需设置 | 关闭 |

从站可加载 [从站示例](../examples/rtu-slave-read-write.json)并将权限改为“只读”；
主站可加载 [FC04 读取示例](../examples/rtu-master-read-input.json)。两端分别修改串口。

启动后，主站 RX 数值在 9～11 之间变化，从站显示对应 TX 数值。切换到“趋势曲线”查看波形。
主站 TX 数值为空正常，读取请求本身不携带测量值。

本软件 RTU 从站的保持区仅用首个源快照初始化。读取持续变化的源数据使用 FC04；
改用 FC03 会读到保持区初始值或后来写入的值。

## 场景二：主站只读，采集实际设备

用于读取仪表或 PLC 的数值。实际设备作为从站，本机选择“RTU 主站、只读”。

1. 按设备点表选择 FC03（保持区）或 FC04（输入区）。测量值也可能位于保持区。
2. 填写设备站号、串口参数和测点地址，核对数据类型及字节序。
3. 启动后查看 RX 数值和通信计数。本机数据源灰显，不参与读取。

本软件测点按 float32 展示，每点占两个寄存器，地址从 0 开始。若厂家点表使用
30001/40001 等编号，须按其地址说明换算为对应区域的零基地址，不能直接填入引用编号。

## 场景三：主站写入，从站保存并读回

用于参数写入、设定值下发及写后校验。两台电脑配置如下：

| 设置项 | 从站电脑 | 主站电脑 |
| --- | --- | --- |
| 模式、权限 | RTU 从站、读写 | RTU 主站、读写 |
| 周期操作 | 无需设置 | FC16 · 写多个寄存器 |
| 测点 | 启用测点 1，地址 0 | 启用测点 1，地址 0 |
| 数据源 | 常量 0，作为初始值 | 常量 1.25，作为写入值 |
| 写后读回间隔 | 无需设置 | 1（每周期读回），功能码 FC03 |

可加载 [从站示例](../examples/rtu-slave-read-write.json)和
[写入读回示例](../examples/rtu-master-write-readback.json)，再调整串口和从站数据源。

主站向保持区地址 0、1 写入 float32 值 1.25，再用 FC03 读回。
预期主站 TX=1.25、RX=1.25，从站保持区 RX=1.25，读回不一致计数为 0。
输入区仍由从站数据源更新，不受写入影响。

只需持续写入时，将写后读回间隔设为 0。此时 ACK 只表示写入应答，不提供新的 RX 浮点值。
连接实际设备时，使用设备点表明确允许写入的地址和数据类型。

## 场景四：使用 FC06 逐寄存器写入

适用于需要测试 FC06，或对端只支持单寄存器写入的情况。
沿用场景三，将主站周期操作改为“FC06 · 逐个写寄存器”；从站仍需“读写”权限。

一个 float32 会拆成两次 16 位写入，不能保证两个寄存器同时更新。
单次报文不足一个完整测点时，实时区显示原始寄存器；启用 FC03 读回后可查看完整浮点值。

## 场景五：TCP 只读从站，供外部程序读取

用于调试支持 Modbus TCP 的上位机或客户端。本软件选择“TCP 只读从站”，
外部程序作为 TCP 主站；本软件目前不提供 TCP 主站或 TCP 写入功能。

加载 [TCP 从站示例](../examples/tcp-slave.json)。同机测试使用 `127.0.0.1:1502`；
跨电脑测试将绑定地址设为本机实际局域网地址，客户端连接该地址和端口。
客户端设站号 1，可用 FC03 或 FC04 读取地址 0、数量 2，得到第一个 float32 测点。

当前 TCP 从站的 FC03/04 共用同一波形快照，均只接受完整测点读取；
RTU 的保持区保存写入、输入区独立更新规则不适用于该 TCP 模式。
当前 TCP 模式未提供实时数值快照，曲线选项灰显；数值由外部客户端读取，原始通信保存在事件日志中。

## 结果检查

- 数值表最多 5 Hz 刷新，曲线为 2 Hz、最近 10 秒；完整通信记录以事件日志为准。
- 超时或停止后保留最后数值，并标记过期或停止；保留值不代表通信仍正常。
- 连续模式遇到通信异常仍可继续运行，应检查超时、协议异常、关联不确定和读回不一致计数。
- 点击“停止并保存”，在“打开结果”中查看配置快照、`summary.json` 和全部 `events*.jsonl` 分片。

| 现象 | 检查项 |
| --- | --- |
| 一直超时 | 主从角色、串口占用、接线、串口参数和站号 |
| 正弦波配置后 FC03 读值不变 | RTU 保持区不会随源波形持续更新，读取波形应使用 FC04 |
| 写入收到异常应答 | 从站是否开放写权限，功能码和地址是否支持 |
| 数值与预期不同 | 寄存器区、零基地址、数据类型和字节序 |

协议约束与详细测试步骤见 [RTU 寄存器读写与实时监视](rtu-register-monitor.md)。
