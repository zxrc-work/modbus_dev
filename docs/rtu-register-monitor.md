# RTU 寄存器读写与实时监视

TCP 与 RTU 从站共用独立寄存器区，支持 FC03、FC04、FC06、FC16；
不增加线圈、离散输入或其他功能码，不修改 STM32 透明转发固件。

## 角色、权限与操作

- 主站主动发起请求，从站处理并应答。同一条 RTU 总线上同时只运行一个主站。
- `access_mode=read-only`：主站仅可读取；从站拒绝写入并返回异常。
- `access_mode=read-write`：允许读写，但不强制每周期先写再读。
- 主站 `points[].operation` 为每个测点选择具体操作：

| 配置值 | 功能 | 寄存器区 |
| --- | --- | --- |
| `read-holding` | FC03 读取 | 保持区 |
| `read-input` | FC04 读取 | 输入区 |
| `write-single` | FC06 逐个写入 | 保持区 |
| `write-multiple` | FC16 批量写入 | 保持区 |

主站纯读取不会先发送 FC16，也不与本机生成的常量 / 正弦 / 三角波值比较。
FC03/04 纯读取只配置读取地址、逐点类型和排列，不创建或采样本机数据源。界面收起数据源参数并说明来源，
后端忽略其数值与能力校验；无关参数保留，切回写入时重新生效。JSON 结构与字段名仍按配置格式检查。
各点写后读回由 `points[].readback_every` 控制，0 为关闭，1 为每周期读回；读回必须使用 FC03，
因为 FC04 是独立输入区，不能用于验证保持区写入。

八个测点可混用 16/32 位整数和 float32，占用宽度及允许排列随类型确定，见[通用数值类型](numeric-types.md)。
FC06 只允许 16 位点；32 位点使用 FC16，不再自动拆写。
RTU 模拟从站允许单个 16 位寄存器读写，不强制所有请求包含完整 32 位点。
读取或写入未映射地址、跨地址空洞会返回异常 02；非法数量、长度、字节数返回异常 03。

## 保持区和输入区

- 从站在首个源快照发布时初始化保持区，之后仅由合法 FC06 / FC16 写入更新。
- 输入区按 `period_ms` 独立生成常量 / 正弦 / 三角波数据，不受主站轮询频率影响，也不被主站写入。
- 保持区在串口重连期间保留，停止会话后不持久化到磁盘；新会话重新初始化。
- FC16 先校验整个请求，再一次性更新范围，非法请求不能部分写入。
- 地址 0 的合法广播写入执行但不应答；其他站号、坏 CRC 和噪声不会成为正常应答。
- 为避免升级后自动开放写权限，旧 JSON 缺少 `access_mode` 时，RTU 从站仍按只读加载。
  需要接收写入时，请在 GUI 明确改为“读写”或加载新的读写示例。
- 配置使用 schema_version=4，兼容迁移版本 1、2、3；旧软件不认识新版本，需要更新后再加载新配置。

## Windows 串口超时更新

Windows 只在打开串口或改变波特率、校验位、流控及 RS485 设置时重配线路；
运行中的读写超时通过 `SetCommTimeouts` 更新，避免每次轮询都再次调用 `SetCommState`。
关闭后重新打开会重新应用完整线路参数。

## 实时数值与曲线

实时数值位于日志上方；“运行日志 / 趋势曲线 / 详细统计”使用标签页切换。
表格按测点、寄存器区域展示 TX / RX 数值、更新时间及状态，鼠标悬停可查看功能码、原始寄存器和数值年龄。

- 主站 TX：实际完整提交到串口驱动的写入数据，不是源计划值。
- 主站 TX 的提交质量和 ACK 确认状态分开：有效 ACK、关联不确定、超时或异常应答只更新确认文字，
  不擦除已提交值，不刷新数值时间，也不额外生成曲线点；提交驱动不等于物理发送完成或设备已执行。
- 主站 RX：通过帧校验并解析出的读取响应；关联不确定、读回不一致会单独标记。
- 从站 RX：已通过校验并写入保持区的数据。
- 从站 TX：读取响应完整提交给驱动后，才显示该次返回的数值。
- 写入 ACK 本身没有测量值，不能伪装成新收到的读取值。
- 单寄存器操作不足以组成 32 位点时，显示原始寄存器，不跨请求拼接；非有限浮点数也显示原始值。
- 超时、重连或停止后保留最后数值，但注明过期 / 停止，不能自动置零或假装仍在更新。

刷新与容量由 `domain/live_policy.py` 统一管理：

| 项目 | 上限 |
| --- | --- |
| worker 状态与数值快照 | 5Hz |
| GUI 数值表 | 5Hz |
| 可见曲线批量重绘 | 2Hz，通信点不按此频率抽取 |
| 曲线时间窗口 | 最近 10 秒 |
| 每条曲线容量 | 最多 10001 个通信点，按原始通信时间戳排列 |
| worker 待传缓冲 | 最多 160016 条，保留最近 10 秒 |
| 单个通信点批次 | 最多 1024 条；最终结果前分批发送剩余点 |

可分别勾选测点及 TX / RX；TX 实线、RX 虚线，区域和方向明确标注。
通信发生时先缓存实际数值，worker 即将写入状态管道时才取出批次，状态包被合并不会丢掉尚未发送的通信点。
GUI 收到批次后立即入曲线缓冲；数值表仍只保留最新值，2Hz 定时器只负责重绘。
例如每秒收到 10 个通信点，每次绘图可新增约 5 个点，最近 10 秒约有 100 个点。
隐藏曲线标签页时停止绘制，但继续缓存最近 10 秒的数据；重新显示即可查看隐藏期间的通信点。
TX 没有新的完整提交或数值无效、过期时留断点；ACK 状态不改变已知的提交值。
RX 关联不确定、读回不一致、数值无效或过期时继续留断点，不将 ACK 展示调整当作接收质量恢复。
超过缓冲容量或管道长期阻塞时淘汰旧记录，界面显示缓冲丢弃数并断线。
通信独立工作进程保持原来的绝对周期调度，不等待界面绘制。
曲线只覆盖当前时间窗口和配置测点，完整通信证据仍以事件日志为准。

## 两台电脑怎样测试

两端同步同一份源码、停止旧 GUI 后重新运行 `python -m modbus_dev gui`。
无需因本轮修改重新打包便携版，也没有新增第三方依赖。
不能只停止再启动会话：已启动的 GUI / worker 仍可能使用旧模块，必须退出并重启 GUI。
以下端口必须替换为各自电脑实际接线对应的串口。

### 测试 A：Windows 读取 Mac 波形

1. Mac 加载 `examples/rtu-slave-read-write.json`，选择实际端口；只读权限也可完成此测试。
2. Windows 加载 `examples/rtu-master-read-input.json`，选择实际 COM 口。
3. 两端设 115200、8N1、站号 1、字节序 B1234；测点起始地址均为 0。
4. 先启动从站，再启动主站。Windows 应收到 FC04 数值并显示 RX 曲线，Mac 显示 TX 曲线。
5. 主站读请求没有测量值载荷，因此主站 TX 数值显示“—”是正常的，原始请求仍记录在日志中。

### 测试 B：写入与读回

1. Mac 从站设为“读写”；Windows 加载 `examples/rtu-master-write-readback.json`。
2. 主站向保持区地址 0、1 写入 1.25，再用 FC03 读回。
3. 主站应显示 TX=1.25、RX=1.25；从站显示 RX 写入值及 TX 读回值。
4. 从站输入区继续产生自己的波形，不得被这次写入覆盖。
5. 改用 FC06 时，一个 float32 会分两次发送，数值不足一个完整点的报文显示原始寄存器。

之后双方停止会话、交换主从角色、交换相应配置，再分别重复 A / B。
本轮没有自动连接真实串口、重启用户现有会话、替 Windows 同步代码或执行硬件验收。

完整的逐点区域、操作、迁移及周期预算规则见 [独立测点与周期预算](point-configuration.md)。
