# 通用数值类型与混合测点

## 范围与数值语义

本工具为采集主程序提供模拟从站、发数与诊断能力。TCP 只读从站、RTU 主站和 RTU 从站
共用逐点类型、排列、宽度及编解码规则，不新增协议、通信角色或现场控制功能。

输入什么数，就按所选类型编码什么数；读取后按所选类型解码显示。本工具不配置比例、
工程偏移或工程值预览，也不自动反算。工程量换算由采集主程序自行配置和处理。
原有正弦源的 `source.value` 是波形中心偏置，不是工程量换算参数。

| 类型 | 范围 | 寄存器数 | 数据源 |
| --- | --- | --- | --- |
| `int16` | -32768～32767，二进制补码 | 1 | 常量 |
| `uint16` | 0～65535 | 1 | 常量 |
| `int32` | -2147483648～2147483647，二进制补码 | 2 | 常量 |
| `uint32` | 0～4294967295 | 2 | 常量 |
| `float32` | IEEE 754 单精度有限值 | 2 | 常量、正弦 |

整数常量必须是整数值，允许 `123` 或 `123.0`，拒绝 `123.5`，不自动取整、截断、钳位或回绕。
整数点不支持正弦源。源值越界、非有限浮点数及非法配置在打开通信设备前报错。
收到非有限浮点位模式时保留原始寄存器并标为无效，不进入有效曲线。
不把整数的 `0xFFFF`、`0xFFFFFFFF` 等合法位模式默认当成故障。
首版不含 64 位、BCD、字符串和位域。

## 逐点配置与排列

`points` 中每项新增 `data_type` 和 `byte_order`。同一通信源最多仍为四个测点，可以混合类型和排列。

| 位宽 | 配置值 | 排列含义 |
| --- | --- | --- |
| 16 位 | `AB` | 高字节在前 |
| 16 位 | `BA` | 交换寄存器内两个字节 |
| 32 位 | `B1234` | ABCD，保持原排列 |
| 32 位 | `B4321` | DCBA，四字节反转 |
| 32 位 | `B2143` | BADC，各寄存器内交换字节 |
| 32 位 | `B3412` | CDAB，交换两个寄存器 |

排列是测点有效载荷的解释规则，不改变 Modbus 地址、数量和寄存器字段自身的线上编码。
不适用的排列在界面中灰显不可选择，JSON 明确指定不匹配排列时直接报错。

省略 `data_type` 时为 `float32`。省略或设 `byte_order=null` 时，16 位点使用 `AB`，
32 位点继承会话级 `byte_order`；明确指定测点排列则覆盖会话默认值。
加载配置版本 1、2 时保留原 float32 和公共排列含义，保存、运行快照统一使用版本 3。
旧版软件不能加载版本 3 配置，需要同步更新工具；旧配置本身不必手工迁移。

```json
{
  "schema_version": 3,
  "mode": "tcp-slave",
  "byte_order": "B1234",
  "points": [
    {"address": 0, "data_type": "int16", "source": {"value": -123}},
    {"address": 1, "data_type": "float32", "byte_order": "B3412", "source": {"value": 12.5}}
  ]
}
```

## 地址、分组与原始寄存器诊断

所有地址均为零基寄存器地址。类型宽度统一用于末地址、重叠检查、请求分组和串口线路预算。
16 位点可放在 65535，32 位点的最大起始地址为 65534；32 位点不要求起始地址为偶数。
相邻完整测点合并，读取或自动发数分组不跨未配置地址，禁用点不占地址。
类型宽度变化不会修改采样周期或超时设置；线路预算不足时仍明确报错。

- TCP 从站继续只支持 FC03/04，要求请求覆盖完整测点；混合类型的合法数量可以是奇数。
  部分点、未绑定地址或跨空洞读取返回异常 02。
- RTU 主站 FC03/04 按完整测点分组；FC16 可在同一笔中编码连续的混合测点。
  FC03 写后读回按原始寄存器逐字比较，不做重新编码或工程换算。
- FC06 每笔只写一个寄存器：16 位点一笔完成。工具保留将 32 位点拆成两笔的已有诊断行为，
  这不是原子更新，不保证被测采集主程序接受；验证主程序完整测点接收时应使用 FC16。
- RTU 模拟从站继续按原始寄存器读写，保持区保留写入，输入区由源时钟独立更新。
  已绑定地址的半点和非有限浮点位模式可保存、读回，用于测试主程序的拒绝或坏数处理。
  FC16 保留原有整范围地址校验和一次性提交，不接受未绑定地址或跨空洞写入。

采集主程序的“禁止 FC06 拼接”“整块只提取绑定点”等是被测端业务规则，
不直接替换本工具模拟从站的原始寄存器规则。
实时显示只解释单次实际通信覆盖的完整点，不跨两次 FC06 拼成有效值；
原始寄存器、类型、排列可在数值提示中核对，32 位整数以完整十进制显示。
ACK 仍仅更新确认状态，不刷新数值时间或补造采样点。
TCP 的实时曲线发布范围沿用现有行为，不因类型扩展新增实时快照。

## 使用与独立验证

- TCP 混合从站：`examples/tcp-mixed-types.json`。
- RTU 混合发数：`examples/rtu-master-mixed-types.json`。先修改串口、站号和对端点表；
  示例中的 COM11 仅为占位，运行会实际写入保持寄存器。
- RTU 模拟从站：`examples/rtu-slave-mixed-types.json`，先修改 COM12 占位串口。
  其点表与 TCP 示例相同；主站发数示例的点表不同，联调前须使双方类型、排列和地址一致。

```sh
modbus-dev validate examples/tcp-mixed-types.json
modbus-dev run examples/tcp-mixed-types.json --output results/mixed-tcp-run
```

在另一终端使用固定报文核对上述 TCP 示例，输出目录须不存在：

```sh
python tools/verify_register_cases.py --host 127.0.0.1 --port 1502 \
  --cases examples/mixed-register-cases.json --output results/mixed-tcp-check
```

诊断工具接收外部 JSON 数组，每项的 `request`、`response` 为不含站号和传输头的十六进制 PDU，
`unit` 默认为 1，`response=null` 表示预期静默。RTU 使用 `--serial-port`，
并按需传入 `--baud`、`--parity`、`--stop-bits`。
样例中若有 FC06/FC16，诊断工具会真实发出写入请求，只应对明确授权的测试对端使用。
核对依据是固定预期字节，不调用生产数值编码器生成答案；每次运行独立保存回执和报文。
`examples/rtu-mixed-register-cases.json` 对应 RTU 模拟从站示例，包含实际写入、半点及非有限位模式注入，
不可当作采集主程序严格接收规则的预期结果；仅用于本工具模拟从站的原始诊断回归。

自动测试的 `tests/fixtures/numeric-vectors.json` 覆盖五种类型的全部允许排列；
编码、解码各自对固定寄存器样例断言，而非只做自编自解。
验收还应覆盖整数上下界、合法全 1 位模式、非有限浮点、混合地址边界、空洞和半点、
旧配置迁移、原始读回、实际 TCP/隔离 PTY，以及 GUI 到 worker 的混合点表传递。
虚拟通信验证不能代替物理 RS485、采集主程序实机互操作或其他平台验收。
