# GUI 设计与高 DPI

界面采用统一浅色设计与 Windows 字体初始化方案，
继续使用 PySide6 6.7.2，不引入第三方 UI 组件库。协议、配置校验和工作进程沿用原有实现。

## 布局与公共样式

- 左侧为会话配置，按“连接与时序 / 数据设置 / 其他设置”分组；通信模式决定 TCP、串口、主站读回字段的显示。
- 连接页集中设置模式、设备连接、站号、统一数据周期、超时、时长、策略和主站读回/调度。
- 数据页顶部设置公共 float32 字节序，下面固定四个独立测点区。各区拥有启用开关、可选名称、
  起始地址数字框、常量/正弦源及相应参数。常量显示“数值”，正弦显示“偏置、振幅、频率”。
  禁用点收起详情但保留参数，重新启用时恢复；不参与通信、地址冲突和线路预算。
- 主站 FC03/04 纯读取时，数据源及其参数灰显，保留读取地址和字节序；从站只读仍可设置数据源。
  地址标签区分读取、写入和本机地址，数据页说明数值由本机生成还是来自对方。
- 控件适用性与后端共用 `domain/usage.py`：无关参数保留草稿，不参与数值及能力校验，切换为有效操作后恢复校验。
  TCP 不使用串口参数，RTU 不使用 TCP 地址端口；非 Windows 的 RTS 切换灰显并忽略。
- 主站显示“轮询周期 / 周期通信预算”，RTU 从站显示“数据更新周期 / 应答写超时”；
  TCP 的超时指不完整请求期限。灰显不影响有效的站号、地址、字节序和通信时序设置。
- 地址旁显示该点占用的两个寄存器；启用点重叠或全部禁用时即时提示，启动前统一校验。
- 日志保留独立放在“其他设置”，不与数据或时序混排。
- 右侧为会话控制、连接摘要、结果目录、关键计数和“运行日志 / 详细统计”。运行失败自动切回日志。
- 会话运行时锁定配置。关键计数来自实际工作进程；运行结束后修改下一次的模式，不会改写上一轮的统计含义。
- RTU 主站首页展示有效 ACK / 有效读应答合计，详细统计保留普通与关联不确定分类。历史关联风险使用独立提示，
  不把历史标记反复表现为新故障；TX 提交质量与确认状态分别展示，确认更新不增加曲线点。
- 窗口按可用桌面设定初始大小；配置与运行区均可滚动。逻辑宽度不足 920 时上下排列，分隔条可拖动。
- `ui/theme.py` 集中定义颜色、字体、调色板、控件状态、逻辑尺寸；页面通过语义角色选择外观。
- `ui/widgets.py` 提供公共卡片、组合框弹层和矢量下拉箭头，保留 Qt 的鼠标、方向键、Enter 和 Escape 交互。

主要规格为正文 14、辅助/日志 13、标题 24、输入/按钮/组合框外部高度 36，面板圆角 8。
全部采用 Qt 逻辑像素，不根据屏幕倍率手动缩放控件。

## 模块与配置生效规则

`gui.py` 保留 `Workbench/create_application/main` 入口。界面实现位于 `ui/`：

| 模块 | 职责 |
| --- | --- |
| `app.py`、`main_window.py` | 应用初始化、主窗口装配和组件协调 |
| `configuration_panel.py`、`point_editor.py` | 三个配置页、表单草稿、局部联动与测点编辑 |
| `session_controller.py` | 工作进程、协议解析、停止期限、结果及临时文件收尾 |
| `monitor_panel.py`、`realtime_panel.py` | 会话操作、状态、统计、原文日志与实时数值/曲线 |
| `theme.py`、`widgets.py` | 视觉规范与公共控件 |
| `i18n.py`、`preferences.py`、`texts.py`、`errors.py` | 翻译、应用偏好和用户可见文案 |

控制器的 `busy` 覆盖启动、运行、重连和停止收尾；只有收尾完成才解除编辑锁定。
配置编辑、加载、保存、校验、结果父目录和语言切换的入口采用同一限制。
普通参数编辑更新表单，模式与数据源只做必要的字段显隐、适用性和摘要联动；
下一次启动统一读取、校验并生成独立的会话配置快照，不要求先导出配置文件。
上一轮配置快照和统计保留自身的会话含义。

## 中英文与应用偏好

“其他设置 → 界面 → 显示语言”提供“跟随系统 / 简体中文 / English”。
语言偏好保存在 `runtime.user_data_directory()/preferences.json`，不进入通信 `TaskConfig`。
系统模式按系统界面语言优先级匹配中文或英文，均不支持时使用英文；macOS 优先读取界面语言偏好。
通信停止后，选择语言立即更新现有控件文案，无需重启应用。历史日志、用户命名、路径和原始报文保留原文。

英文作为源文案，中文通过 `translations/modbus_dev_zh_CN.ts` 及其编译产物 `.qm` 提供。
`tr()` 标记源模板；`bind()` 记录控件的文字、标题、提示和无障碍名称等绑定。
带参数模板先翻译后填值；下拉选项显示文案与协议值分离，语言刷新使用信号阻断保留选择及手工输入。
各组件的 `retranslate_ui()` 刷新文案，不重新应用配置，不进行通信配置校验。
结构化配置错误在界面翻译，CLI 原始诊断与底层异常详情保持原样，核心模块不依赖 Qt。

语言偏好采用临时文件加原子替换写入，写入失败保持原语言和选项。缺失中文资源时，启动使用英文并记录提示。
Qt 标准控件加载相应的 Qt 翻译；操作系统原生对话框内的系统文案由操作系统控制。

新增文案后，运行以下命令提取缺失条目、填写中文翻译，再检查和编译；`.ts` 与 `.qm` 一同提交：

```sh
python tools/translations.py --update
python tools/translations.py --check
python tools/translations.py --compile
```

检查会拒绝缺失、未完成、重复的翻译和格式参数不一致；发布构建自动检查并编译翻译。

## Windows 清晰度

在首次创建 QApplication **之前**，默认选择 `windows:fontengine=gdi`，并设置
`PassThrough` 分数缩放策略。已显式设置的 `QT_QPA_PLATFORM` 和
`QT_SCALE_FACTOR_ROUNDING_POLICY` 会保留，不覆盖离屏测试或调用方设置。

正文按已安装字体选择 Segoe UI、微软雅黑/微软雅黑 UI 等字体并保留中文回退；
Windows 设置 `PreferFullHinting`，日志使用等宽字体并继承同一渲染偏好。
Qt 负责逐显示器 DPI 感知、窗口跨屏缩放和按实际像素渲染；不关闭系统高 DPI 缩放，
也不把低分辨率界面截图拉大。参见 [Qt 高 DPI 文档](https://doc.qt.io/qt-6/highdpi.html)。

这次处理覆盖源码入口 `python -m modbus_dev gui` 和 `modbus-dev-gui`。
独立 exe 安装包尚未交付；后续打包需另加 Per-Monitor V2 清单并验证实际 exe，不能用源码窗口测试代替。

## 预览和回归

不打开串口、不启动会话，生成三个模式的三组配置页、四测点滚动截图及组合框弹层截图：

```powershell
python tools/preview_gui.py --output-dir results/gui-preview/offscreen
python tools/preview_gui.py --native --output-dir results/gui-preview/windows
python tools/preview_gui.py --native --language en --output-dir results/gui-preview/english
python -m unittest discover -s tests -v
```

`--native` 使用隐藏的 Windows 原生窗口，不显示到桌面。
输出的 `report.json` 记录窗口逻辑尺寸、截图实际像素、DPR、字体、hinting、
控件高度及窗口是否获得 Per-Monitor V2。`--scale` 是相对系统原生倍率的测试乘数，
例如系统为 150% 时 `--scale 2` 得到 300%，不是 200%。

`tests/test_gui_display.py` 在独立进程中按原生倍率换算，测试 100%、125%、150%、175%、200%
及当前系统倍率，同时验证窄屏字段与启动操作可通过滚动访问。
`tests/test_gui_worker.py` 覆盖配置往返、下拉框键盘交互、字段状态、计数、
本机 TCP 读数、启动/停止/重启、崩溃和关闭收尾。

离屏截图不作为 Windows 字体清晰度结论；原生测试也不代替不同物理显示器间拖动、
Windows 输入法或麒麟桌面的实机验收。

## 配置与实现边界

- `ui/point_editor.py` 封装可复用测点编辑器；地址冲突规则与领域配置共用，不在界面复制通信逻辑。
- schema_version=2 使用 `points` 数组，最多四项，不足四项补为禁用槽位。每点独立保存
  `enabled/name/address/source`；`unit/byte_order/period_ms` 等仍为设备级设置。
- 旧 schema_version=1 的 `addresses + source` 在加载边界展开成多个独立测点，初始保留原来的
  同源行为；保存时写新版配置，运行时不再维护两套数据路径。worker 的 JSONL 协议仍为版本 1，
  与会话配置版本独立。
- 生成数据时按统一时间槽计算各启用点，映射时连同其数值按地址排序；纯读取只按地址生成请求，
  不创建、采样数据源或进行写入值编码。连续地址可合并，跨禁用空洞不得连读/连写。
- 曲线仅允许勾选当前操作可产生的寄存器数值方向：读取主站为 RX，写入主站为 TX，启用读回后增加 RX；
  RTU 只读从站为 TX，读写从站增加保持区 RX。输入区 RX 及当前未提供数值快照的 TCP 曲线灰显。
- 数值表保留最新值，曲线单独缓存实际通信点和原始时间戳；worker 分批传输，GUI 接收与 2Hz 重绘分离。
  隐藏曲线页继续缓存最近 10 秒，容量与溢出规则见 [RTU 数值与趋势](rtu-register-monitor.md)。
- 新版源码不会更新已经编译的便携包。Windows/麒麟显示、发布包及物理总线需要分别重新验收。
